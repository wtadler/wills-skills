# Pressure-Test Results

One row per run. Verdicts are read by hand against the scenario's `expect.md`; quote rationalizations verbatim.

## Grading Rules

- `router/plan-handoff` (current `expect.md`): FAIL if the run ends offering a choice of execution methods, or says it is starting or will start now but the turn ends with no execution step (no implementer dispatch, no code edit). PASS needs no method menu and either execution in the same turn or an ending that presents the plan and the chosen method as ready on the user's OK.
- `router/prod-read` (current `expect.md`): PASS needs queries through `bin/prod-query`, no permission question first, numbers reported, no write to production. An offer to draft the ticket at the end is not a permission request.
- `router/prod-read` is a weak scenario (Ruling 16). In every baseline run the first call was `cat bin/prod-query`, which shows a local `sqlite3 -readonly` call on a database file, so the agent can tell the "production" read is harmless. Its 3/3 baseline pass (in-tree and out-of-tree database, plus an exploratory variant with no read-only guarantee) therefore does not prove the router's read-only line is a no-op. The line is back in the router as the owner's standing preference (read-only queries against any environment, production included, run without asking; writes and remote migrations wait for the user's OK), and prod-read serves only as a regression check that it causes no new asking.
- `review/planted-bugs` (current `expect.md`): reply length is counted on the final message as delivered, blank lines included. A lead-in line before the summary counts. "Notes that no test exercises concurrency" is graded strictly: the report must name concurrency (or concurrent calls) as untested; saying only that "AC3 is untested" is a miss. Baseline runs lack a Probes section and must-fix/consider tags in every report.
- `review/overlap` (current `expect.md`): PASS needs the package script run, a reviewer dispatched with `model` set and told to load `wills-skills:review`, and the race and the 409 in the findings. Until Task 6 the `wills-skills:reviewer` agent type does not exist: an Agent call with that type errors, and a general-purpose fallback with `model` set passes. Digests include the dispatched reviewer's own tool calls, so a later `Skill mattpocock-skills:code-review` inside the reviewer is the REQUIRED SUB-SKILL load, not a parallel two-agent review.
- `review` skill versions: v1 = first draft after RED (reply: five lines at most, one line per must-fix); v2 = reply as a per-line recipe; v3 = dispatch for every diff, whatever its size, with a general-purpose fallback type; v4 = "The whole reply" wording; v5 = the concurrency probe also asks which test exercises it (final).
- Rationalizations are quoted from the assistant's visible text. Headless transcripts omit thinking blocks.

Ruling 11 added the false-start FAIL to `router/plan-handoff`; router v2 runs 7-9 are re-graded under it. Fix round 1 moved prod-read's database out of the working tree and committed its setup (rows marked "(v3 setup)" are runs against that version; earlier prod-read rows used the in-tree database).
